# Stems (Backing Track) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Start from the [runbook](2026-11-07-overnight-runbook.md).

**Goal:** After a song is imported, the server splits it with Demucs and saves three ready-made mixes (Backing track, No vocals, Vocals only); a Mix button in the player bar switches between them and the full song.

**Architecture:** Demucs runs as a **follow-up after a successful import**, on the same single worker, after the import job is already marked done (so the song opens right away). It writes three mixed AAC files; the browser switches the one `<audio>` element's source, keeping position, speed and play state. No multi-track playback, no player changes, no task queue. Songs imported earlier are filled in by a script. Every song write goes through a locked `update_song`, and autosave can't erase the server-written fields.

**Tech Stack:** Python 3.12, FastAPI, `demucs==4.1.0`, soundfile, imageio-ffmpeg, pytest · React, Zustand, Vitest.

**Spec:** `docs/ROADMAP-DESIGN.md` §3, §4.4. Reference code: `docs/superpowers/plans/spikes/stems_spike.py` (proven: 22 s per song on `mps`).

## Global Constraints

- Everything in the runbook §2. Smallest diff that works.
- Mixes (names, in this order): `backing` = vocals + drums + bass (the keys/guitar part is yours to play); `novocals` = drums + bass + other; `vocals` = vocals. Files: `songs/<id>/mix/<name>.m4a`, AAC 128 kbps, 44.1 kHz stereo. `song.json` gets `"mixes": ["backing", "novocals", "vocals"]`.
- Device: `mps` if `torch.backends.mps.is_available()`, else `cpu`. Import `demucs`/`torch` inside `DemucsSeparator` methods only.
- A follow-up failure is logged and never changes the import job's state.
- Copy (exact): the Mix button text is the current mix's name: `Full song`, `Backing track`, `No vocals`, `Vocals only`; title `Mix: tap to switch between the full song, a backing track, no vocals and vocals only`. Hidden when the song has no `mixes`.

## Review Focus

1. **A tab opened before the split finished autosaves afterwards**: `mixes` survive the PUT. Pinned in Task 1.
2. **A song deleted while its split is running**: the split fails cleanly and must not recreate the song folder. Pinned in Task 1 (`update_song on a missing song raises`) and Task 2 (`split of a deleted song leaves no folder`).
3. **Switching mix mid-song** keeps position, speed and play/pause. Pinned in Task 3 (`switchMix keeps position and rate`).
4. **A saved mix preference on a song without mixes** (or a mix that's missing) falls back to the full song. Pinned in Task 3.
5. **Import failure**: no split runs. Pinned in Task 2.

**Interfaces:**
- Produces:

  - `SongStore.update_song(song_id: str, change: Callable[[dict], dict]) -> dict` — under the lock: read `song.json` (raise `FileNotFoundError` when it doesn't exist; **never** create the folder), apply `change`, write atomically, return the result.
  - `def keep_server_fields(stored: dict, incoming: dict) -> tuple[dict, bool]` in `store.py` — `merged` = `incoming` with `mixes` from `stored` (removed if `stored` has none), and each incoming lyric line's `words` taken from the stored line with the same `id` **and** `text` (else removed). The bool is `True` when any incoming non-empty line's `(id, text)` isn't in `stored` (plan 5 uses it).
  - PUT saves with `update_song(id, lambda stored: keep_server_fields(stored, incoming)[0])`.

### Task 2: Split after import, serve the mixes, fill in old songs

**Files:**
- Create: `server/app/stems.py`, `server/scripts/backfill.py`, `server/tests/test_stems.py`
- Modify: `server/pyproject.toml` (`uv add demucs==4.1.0`), `server/app/pipeline.py` (`Deps.separator`), `server/app/jobs.py`, `server/app/main.py`
- Test: `server/tests/test_api.py`

**Interfaces:**
- Consumes: `update_song` (Task 1).
- Produces:
  - `MIXES = ("backing", "novocals", "vocals")`
  - `class StemSeparator(Protocol): def separate(self, audio: Path, out_dir: Path) -> dict[str, Path]: ...` — writes `out_dir/<mix>.m4a` for each of `MIXES`.
  - `class DemucsSeparator` — decode `audio` with the bundled ffmpeg to 44.1 kHz stereo float32 (temp WAV + `soundfile`), `demucs.api.Separator(model="htdemucs", device=…)` created once per instance, `separate_tensor`, sum stems per mix, encode each with ffmpeg (`-f f32le -ar 44100 -ac 2 -i - -c:a aac -b:a 128k`). Follow `spikes/stems_spike.py`.
  - `def split_song(song_id: str, deps: Deps) -> None` — read the song (raises if missing), separate into a `tempfile.TemporaryDirectory()`, then `update_song(id, change)` where `change` moves the files into `song_dir/"mix"` and returns `{**song, "mixes": list(MIXES)}`. Because `update_song` raises before calling `change` when the song is gone, a deleted song's folder is never recreated.
  - `Deps.separator: StemSeparator | None = None`; the real app sets `DemucsSeparator()`.
  - `JobRunner.after_import: list[Callable[[str, Deps], None]]` — `[split_song]` when `deps.separator` is set. In `_run`, after the import's final state is set and is `done` or `done_without_lyrics`, call each in turn inside `try/except`, logging failures (`logging.getLogger(__name__).exception`).
  - `JobRunner.run_later(fn: Callable[..., None], *args) -> None` — submits to the same single-worker pool, logging failures (plan 5 uses it).
  - `GET /api/songs/{id}/mix/{name}` → `FileResponse` (Range works); 404 for an unknown name, a missing song or a missing file.
  - `scripts/backfill.py [--stems] [--align] [song ids…]` — data folder from `PC_DATA_DIR` (same default as `main.py`); with no ids, every song missing the result; prints seconds per song. `--align` is added in plan 5.

  - The waveform keeps using the full song (`api.audioUrl`), unchanged.
