# Wait-for-me Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Start from the [runbook](2026-11-07-overnight-runbook.md).

**Goal:** With "Check my playing" on, the song stops exactly at each chord change and carries on the moment the mic hears you play the new chord.

**Architecture:** The stop is a gate in the clock, next to looping, so it's frame-accurate. All the rules (when to move the gate, resume, give up waiting) live in one pure function, `waitAction`; the existing practice interval calls it and applies the result. Wait mode is for learning, so its runs aren't scored.

**Tech Stack:** React 19, Zustand 5, Vitest 5, TypeScript.

**Spec:** `docs/ROADMAP-DESIGN.md` §4.1.

## Global Constraints

- Everything in the runbook §2. Smallest diff that works: no new modules beyond those named here.
- The gate stops playback only when playback **crosses** it in one small step (`time - prev < 0.25 s`); seeks and loop jumps never trigger it.
- Chords shorter than **½ beat** (song time) and N.C. are never waited on.
- While waiting, `playbackStore.playing` stays `true`, `waiting` is `true`, and the audio element is paused.
- **No scoring in wait mode:** the run tracker sees "not playing" while `waitMode` is on, so turning it on ends and saves the current run, and nothing is scored until it's off.
- Copy (exact): toggle `Wait for me`, title `Wait for me (W): the song waits at each change until you play it`; while waiting `Waiting for {chord}. Play it to carry on.`; button `Skip`; score area in wait mode `Scores are off in Wait for me`.

## Review Focus

1. **Scrubbing or clicking a chord while waiting** ends waiting and leaves playback paused; it never snaps back. Pinned in Task 1 (`release when you move away`).
2. **Space while waiting** stops like any pause. Pinned in Task 2 (`togglePlay while waiting`).
3. **Turning wait mode off while waiting** resumes playback. Pinned in Task 1.
4. **A loop in wait mode**: the jump back never trips the gate. Pinned in Task 1 (`gateStop ignores jumps`) and Task 2 (clock test).
5. **Stopping Check my playing while waiting** leaves no stuck gate. Pinned in Task 2 (strip cleanup step + check).

### Task 1: Wait rules as pure functions

**Files:**
- Modify: `web/src/domain/timing.ts`
- Test: `web/src/domain/timing.test.ts`

**Interfaces:**
- Produces:
  - `export function gateStop(prev: number, time: number, gateAt: number | null): number | null` — `gateAt` when `prev < gateAt <= time && time - prev < 0.25`, else `null`.
  - `export function nextGateAt(chords: ChordEvent[], index: number, songBeat: number): number | null` — start of the first chord after `index` (from 0 when `index === -1`) with `chord.kind === 'chord'` and length ≥ `songBeat / 2`; `null` if none.
  - `export type WaitAction = 'none' | 'setGate' | 'resume' | 'release' | 'clear'`
  - `export function waitAction(s: { waitMode: boolean; playing: boolean; waiting: boolean; time: number; gate: number | null; gateAt: number | null; hit: boolean }): WaitAction`, in this order:
    1. `!waitMode`: `waiting` → `'resume'`; `gate !== null` → `'clear'`; else `'none'`.
    2. `waiting`: `gate !== null && |time - gate| > 0.05` → `'release'`; `hit` → `'resume'`; else `'none'`.
    3. `playing && gate !== gateAt` → `'setGate'`.
    4. `'none'`.

### Task 2: Wire the gate: store, clock, play/pause, practice interval

**Files:**
- Modify: `web/src/state/playbackStore.ts`, `web/src/services/clock.ts`, `web/src/state/studioSession.ts`, `web/src/features/player/PlayerBar.tsx`, `web/src/state/judgeStore.ts`, `web/src/features/judge/Practice.tsx`
- Create: `web/src/services/clock.test.ts`
- Test: `web/src/state/studioSession.test.ts`

**Interfaces:**
- Consumes: `gateStop`, `nextGateAt`, `waitAction` (Task 1).
- Produces:
  - `playbackStore`: `gate: number | null`, `waiting: boolean`, `setGate`, `setWaiting` (not persisted; `openStudio`'s close resets both).
  - `startClock(player, onTick, getLoop, getGate: () => number | null = () => null, onGate: (at: number) => void = () => {})` — remembers the previous frame's time; when `gateStop(prev, time, getGate())` returns `at`, calls `onGate(at)` then `onTick(at)`.
  - `openStudio` passes `() => usePlaybackStore.getState().gate` and `(at) => { player.pause(); player.seek(at); usePlaybackStore.getState().setWaiting(true); }`.
  - `PlayerBar.tsx`: `export function resumeFromWait(nextGate: number | null)` → `setGate(nextGate)`, `setWaiting(false)`, `player.play()`, in that order. `togglePlay()`: when `playing && waiting` → `setWaiting(false)`, `setPlaying(false)`.
  - `judgeStore`: `waitMode: boolean`, `toggleWait()` (turning it on also sets `listening: true`).
  - In `PracticeStrip`'s interval, after the existing work: compute `gateAt = nextGateAt(song.chords, index, songBeat)` in the render-time ref; call `waitAction` with `hit = settled?.grade === 'right'`, and apply: `setGate` → `setGate(gateAt)`; `resume` → `resumeFromWait(waitMode ? gateAt : null)`; `release` → `setWaiting(false)`, `setPlaying(false)`; `clear` → `setGate(null)`. Pass `playing: playing && !waitMode` to `tracker.tick` and to the "playback stopped" check, so wait mode ends the run and scores nothing. The interval's `stop` also calls `setGate(null)` and `setWaiting(false)`.
